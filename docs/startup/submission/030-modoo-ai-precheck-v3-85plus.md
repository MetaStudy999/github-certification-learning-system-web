# Q2. 아이디어를 떠올린 배경 이야기

Git을 배우기 위해 온라인 강의를 들었지만, 브랜치·커밋·머지 개념을 아는 것과 실제 프로젝트에서 “지금 무엇을 해야 하는지” 판단하는 것은 다른 문제였습니다. 이 문제를 가장 크게 체감한 것은 코디세이(Codyssey) GitHub 팀프로젝트였습니다. 브랜치를 나누고 변경사항을 합치며 충돌과 오류를 해결하는 과정에서 AI 어시스턴트를 사용했고, 현재 상황과 오류 메시지를 질문해 문제를 하나씩 해결했습니다.

하지만 AI가 그 순간 답을 알려주어도 시간이 지나 같은 상황을 만나면 다시 검색하거나 처음부터 질문하게 되었습니다. 특히 `rebase`, `stash`, `cherry-pick`, `reflog`처럼 자주 쓰지 않는 기능은 경험이 있어도 다시 확인하게 됩니다. 저는 여기서 “문제 해결”과 “내 기술로 체화” 사이에 빈틈이 있다고 보았습니다.

그래서 현재 브랜치·커밋 상태를 확인하고, 다음 명령과 이유를 단계별로 설명하며, 해결 후에는 성공 과정을 다시 재현해 직접 같은 문제를 풀어보게 하는 AI Git 코치를 구상했습니다. 예를 들어 push 오류를 해결했다면 당시 상태와 명령 순서, 결과를 저장해 다시 보거나 직접 재수행하도록 합니다. 정답을 즉시 보여주기보다 단계별 힌트를 제공하고 도움 없이 다시 해결했는지를 확인합니다.

GitHub의 2025 Octoverse는 전 세계 GitHub 개발자가 1억 8천만 명을 넘었다고 집계했고, 2023년 자료에서는 한국 개발자가 190만 명 이상으로 제시됐습니다. 이 전체를 고객으로 간주하지 않고, 초기에는 **Git을 실제 프로젝트에서 사용하기 시작해 오류 해결과 반복학습이 필요한 초·중급 개발 학습자** 한 집단에 집중해 문제 강도와 지불의사를 검증하겠습니다.

> **3차 실행 전 실제 인터뷰 결과 2~3문장 삽입:** `[인터뷰 결과 입력]`

# Q3-1. 어떤 문제를 해결하며, 기존 방식 대비 차별성은 무엇인가요?

초기 고객의 핵심 문제는 명령어 자체를 모르는 것이 아니라 **현재 저장소 상태에서 어떤 명령을 안전하게 써야 하는지 판단하기 어렵고, 한번 해결한 문제도 다시 혼자 해결하기 어렵다는 것**입니다.

현재 대안은 강점이 서로 다릅니다. GitHub Copilot CLI는 터미널에서 질문·코딩·작업 수행을 지원하는 AI 에이전트이고, GitLens는 Commit Graph·파일 이력·AI 설명으로 Git 상태 이해를 돕습니다. Learn Git Branching은 브라우저에서 Git 저장소를 시뮬레이션하며 단계별 학습을 제공하고, Oh My Git!은 실제 Git과 통합 터미널을 사용해 저장소 내부 구조를 실시간 시각화합니다.

AI Git Coach는 이들과 동일한 기능을 모두 대체하려는 제품이 아닙니다. 초기 차별점은 **실제 사용자의 오류 해결 세션을 안전하게 끝낸 뒤, 그 성공 과정을 그대로 다시 훈련 자산으로 전환하는 흐름**에 집중하는 것입니다.

1단계에서 자연어 또는 오류 메시지를 입력하면 `git status`, 현재 브랜치, 원격 저장소 등 읽기 중심 상태 확인을 우선합니다. `reset --hard`, `clean`, 강제 push처럼 손실 가능성이 있는 명령은 바로 실행시키지 않고 경고·백업·복구 경로를 먼저 안내합니다. 2단계에서는 Git Graph로 현재 위치와 변화 이유를 보여줍니다. 3단계에서는 해결된 세션을 이벤트로 저장해 Replay로 다시 보고, 동일 상황에서 직접 명령을 입력하는 Guided Practice로 전환합니다.

이 구조의 핵심은 **AI에게 물어보고 끝나는 문제 해결을 “다시 해낼 수 있는 역량”으로 바꾸는 것**입니다. 초기에는 이 한 가지 가치를 검증하고, 자격증 준비도·Local/Cloud 모델 선택·교육영상은 검증 이후 확장합니다. 이는 Git 진입장벽을 낮춰 비전공자와 초급 개발자의 실무 적응을 돕는 효과도 기대할 수 있습니다.

# Q3-2. 수익 창출 계획은 어떻게 되나요?

초기에는 B2C 개인 사용자의 반복 사용과 지불의사부터 검증하고, 기관용 모델은 이후 PoC로 확인합니다.

무료 버전에서는 제한된 Git 오류 진단과 기본 가이드를 제공하고, Pro에서는 해결 이력 저장, 고급 진단, Replay, 직접 따라하기 훈련, 반복 취약문제 분석을 제공합니다. **초기 가격 가설은 월 9,900원**입니다. 이는 현재 GitHub Copilot Pro가 월 10달러인 개발자 AI 도구 시장의 가격대를 참고한 검증용 가설이며, 실제 가격은 사용자 인터뷰와 결제 실험으로 조정합니다.

12개월 매출 숫자는 예측이 아니라 **최소 성공기준**으로 관리합니다. 6개월 내 베타 사용자 50명을 확보하고, 7일 재사용률 40% 이상을 목표로 합니다. 9개월까지 실제 유료 사용자 10명 이상을 확보하면 월 9,900원 기준 최소 MRR 99,000원을 확인할 수 있습니다. 12개월에는 누적 가입자 500명, 유료 사용자 50명, B2C MRR 495,000원을 목표 가설로 두고 실제 데이터에 따라 수정합니다.

기관용은 대학·부트캠프·개발교육팀에 실습 진행상황, 반복 오류 분석, Replay 훈련을 제공하는 라이선스를 제안합니다. 초기에는 3개 후보 기관·팀에 데모와 PoC 제안서를 전달하고 **유료 또는 비용지불 의사가 확인되는 실증 1곳**을 최소 목표로 둡니다. 기관 단가는 첫 PoC에서 실제 예산과 운영비를 확인한 뒤 결정합니다.

초기 개발은 기존 공개 저장소와 오픈소스 도구를 활용해 고정비를 낮추고, `[실제 초기 운영자금 방식: 자기자본/지원금/기타]`을 명확히 기재합니다. 핵심 지표는 첫 해결 완료율, D7 재사용률, Replay 전환율, 무힌트 재현 성공률, 유료 사용자 수와 기관 PoC입니다.

> **3차 실행 전 실제 지불의사 인터뷰 수치 추가:** `[결과 입력]`

# Q4-1. 아이디어를 어떻게 사업화하실 계획인가요?

1년 안에 **“실제 Git 문제를 해결하기 위해 다시 방문하고, 해결 경험을 직접 재훈련하며, 이 기능에 비용을 지불하는가”**를 검증하겠습니다. 1인 개발 리스크를 줄이기 위해 MVP를 월별로 순차 검증합니다.

**1개월차 — Core MVP 하나에 집중**  
자연어·오류 메시지 입력 → `git status` 등 상태 확인 → 안전한 단계별 명령 제안 → 실행 결과 확인의 한 흐름만 완성합니다. 현재 공개 GitHub 저장소에서 `/coach-demo` 3열 UI와 `/api/coach` 기반 질의 처리, `reset --hard`·force push 등 고위험 명령 경고 로직을 직접 구현 중입니다.

**2개월차 — 이해와 안전성 강화**  
1개월차 사용성이 확인되면 Git Graph 시각화와 Safety Guard를 보강합니다. 첫 문제 해결 완료율과 오류 해결시간을 측정합니다.

**3개월차 — 핵심 차별기능 검증**  
성공 세션을 상태·명령·결과 이벤트로 저장하고 Replay와 직접 따라하기 훈련을 추가합니다. Replay 사용률, 직접 훈련 전환율, 무힌트 재현 성공률을 측정합니다.

**4~6개월 — 6주 베타 50명**  
Git/GitHub 학습 커뮤니티, 개발 학습자 네트워크, 공개 GitHub 저장소를 통해 50명을 모집합니다. D7 재사용률 40% 이상을 핵심 기준으로 두고, 반응이 없는 기능은 확장하지 않습니다.

**7~9개월 — 첫 결제 검증**  
Pro 유료 사용자 10명 이상과 기관·팀 PoC 1곳을 최소 성공기준으로 검증합니다.

**10~12개월 — 검증된 기능만 확장**  
GitHub 자격증 준비도, Local/Cloud/Hybrid LLM, AI 교육콘텐츠, CLI/IDE 연동은 핵심 루프의 반복사용이 확인된 뒤 순차 개발합니다.

현재 개발 증빙: `https://github.com/MetaStudy999/github-certification-learning-system-web` / branch `feature/ai-git-coach-mvp`.

# Q4-2. 책임멘토를 통해 어떤 도움을 받고 싶으신가요?

책임멘토에게 기능 아이디어 추가보다 **사업 검증의 우선순위와 외부 연결**을 요청하고 싶습니다.

첫째, 초기 고객을 Git을 실제 프로젝트에서 쓰기 시작한 초·중급 개발 학습자로 좁힌 것이 타당한지 검토받고, 1개월 안에 사용할 고객 인터뷰 질문과 문제강도·지불의사 판정기준을 함께 확정하고 싶습니다.

둘째, Core MVP를 “오류 입력 → 상태 확인 → 안전한 단계별 안내 → 결과 검증” 한 흐름으로 제한한 뒤, 어떤 지표가 확인될 때 Replay 기능을 추가해야 하는지 Go/No-Go 기준을 정하고 싶습니다.

셋째, 6주 베타 50명과 유료 사용자 10명이라는 최소 성공기준이 현실적인지 검토받고, 대학·부트캠프·기업 개발교육팀 중 **PoC 후보 기관 1~2곳을 연결하거나 접근 전략**을 자문받고 싶습니다.

넷째, 1인 팀의 약점을 줄이기 위해 6개월 내 확보할 외부 협력 역할을 구체화하고 싶습니다. Git 실무 전문가에게는 명령·복구 시나리오 검수, AI·보안 전문가에게는 모델·소스코드 보호 검토, 교육 전문가에게는 재현훈련 효과 검증을 월 단위 자문 형태로 요청하는 계획입니다. 멘토링을 통해 우선 필요한 1개 역할부터 정하고 확보 경로를 만들고 싶습니다.

# Q8. 창업자(대표)의 역량과 경험을 적어주세요

컴퓨터공학과 법학을 공부했고, 출판편집디자인·제안서·웹마스터·서버관리·IDC 운영 등 기술·콘텐츠·시스템 운영을 함께 경험했습니다. 현재는 AI·보안 융합 분야를 학습·연구하면서 Git/GitHub, Linux, AI 도구를 실제 개발환경에서 사용하고 있습니다.

아이디어의 출발점은 코디세이 GitHub 팀프로젝트에서 직접 브랜치·병합·충돌·오류 해결을 경험한 것입니다. AI 도움으로 문제를 해결하면서 “답을 얻는 것”과 “다음에 혼자 다시 해결하는 것” 사이에 차이가 있음을 체감했고, 이를 제품 문제로 정의했습니다.

현재 말로만 기획하는 단계가 아니라 공개 GitHub 저장소에서 프로토타입을 직접 개발하고 있습니다.

- 저장소: `https://github.com/MetaStudy999/github-certification-learning-system-web`
- 작업 브랜치: `feature/ai-git-coach-mvp`
- 구현 중인 화면: Git Graph + Guided Terminal + AI Coach 3열 `/coach-demo`
- API: 자연어 Git 질문을 단계별 안전 명령으로 변환하는 `/api/coach`
- 안전 로직: `reset --hard`, `clean`, force push 등 고위험 명령 감지 및 백업·복구 우선 안내
- 별도 실험: GitHub 자격증 준비도 대시보드 프로토타입

강점은 개발뿐 아니라 입문자가 이해하기 쉬운 설명, 시각화, 실습 절차, 오류 대응과 검증기준을 한 흐름으로 설계할 수 있다는 점입니다. 다만 현재 1인 팀이라는 한계를 명확히 인식하고 있습니다. 1~3개월은 Core MVP와 사용자검증에 집중하고, 4~6개월에는 실제 검증 결과를 바탕으로 Git 실무·AI보안·교육 중 가장 부족한 역할부터 외부 자문 또는 파트타임 협력 형태로 확보하겠습니다.

| GitHub Copilot CLI | 터미널 AI 에이전트, 질문·코딩·작업 수행, 모델 사용 | 실제 Git 오류의 성공 세션을 Replay·재훈련 자산으로 전환 |
| GitLens / GitKraken | Commit Graph, Git 이력, AI 설명, conflict/AI 기능 | 실제 문제 해결 직후 동일 상황을 다시 직접 수행하는 학습 루프 |
| Learn Git Branching | 브라우저 Git 시뮬레이션, 시각적 단계별 학습 | 사용자의 실제 저장소 오류 맥락과 성공 세션 재사용 |
| Oh My Git! | 실제 Git, 실시간 저장소 시각화, 통합 터미널, 게임형 학습 | 실제 업무 오류 → 안전 해결 → 성공경험 Replay/Guided Practice 연결 |

> 경쟁사가 기능을 전혀 갖고 있지 않다고 단정하지 않는다. **우리의 초기 검증 초점이 ‘실제 오류 해결 경험을 다시 해낼 수 있는 훈련으로 전환’하는 결합 흐름**임을 명확히 한다.
