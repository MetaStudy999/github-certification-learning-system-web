## 0. 이번 2차 문안의 수정 원칙

1차 사전점검에서 가장 큰 감점 요인은 **1인 창업자가 1~3개월 안에 너무 많은 기능을 동시에 구현한다고 보이는 점**이었다.

따라서 제출 문안에서는 초기 MVP를 아래 3가지 핵심 기능으로 축소한다.

1. **자연어 Git 문제 진단**
2. **Git Graph + 안전한 단계별 해결 안내**
3. **성공 작업 Replay + 직접 따라하기 훈련**

다음 기능은 실제 개발에서는 계속 진행할 수 있지만 제출 문안에서는 2단계 이후 확장 기능으로 배치한다.

- GitHub 자격증 준비도 고도화
- Local / Cloud / Hybrid LLM 선택
- AI 교육영상 자동 제작
- 기업용 AI 사용정책
- CLI / IDE 연동
- 자동 모델 선택

핵심 메시지:

> **실제 Git 문제를 AI와 안전하게 해결하고, 해결한 과정을 다시 재현·훈련해 사용자의 실제 역량으로 전환한다.**

# Q2. 아이디어를 떠올린 배경 이야기

Git을 배우기 위해 온라인 강의를 들어 보았지만, 브랜치·커밋·머지 같은 개념을 아는 것과 실제 프로젝트에서 “지금 무엇을 해야 하는지” 판단하는 것은 전혀 다른 문제였습니다.

이 문제를 가장 크게 체감한 것은 코디세이(Codyssey) GitHub 팀프로젝트였습니다. 팀원들과 브랜치를 나누고 변경사항을 합치며 충돌과 오류를 해결하는 과정에서 AI 어시스턴트를 활용했습니다. 현재 상황과 오류 메시지를 질문하면 원인과 해결 방법을 설명받을 수 있었고 실제 문제를 하나씩 해결할 수 있었습니다.

하지만 여기서 또 다른 문제가 보였습니다. AI가 답을 알려주어 그 순간 문제를 해결하더라도, 시간이 지나 같은 상황을 만나면 다시 검색하거나 AI에게 처음부터 물어보게 된다는 점입니다. 실제로 Git은 자주 쓰는 명령과 가끔 쓰는 명령의 격차가 크고, `rebase`, `stash`, `cherry-pick`, `reflog` 같은 기능은 경험이 있는 사용자도 오랜만에 사용하면 다시 확인하게 됩니다.

그래서 단순히 정답을 알려주는 AI보다, 현재 브랜치와 커밋 흐름을 Git Graph로 보여주고, 지금 입력해야 할 명령과 그 이유를 한 단계씩 설명하며, 해결이 끝난 뒤에는 그 성공 과정을 다시 재현해 사용자가 직접 같은 문제를 풀어보게 하는 코치가 필요하다고 생각했습니다.

예를 들어 push 오류를 해결했다면 당시의 상태, 실행한 명령, 결과, Git Graph 변화를 저장하고 나중에 Replay로 다시 보거나 직접 터미널에 같은 명령을 입력해 해결하도록 훈련합니다. 이 과정에서 AI가 정답을 즉시 대신 주기보다 단계별 힌트를 제공하고, 사용자가 도움 없이 다시 해결했는지를 확인합니다.

이 경험을 바탕으로 **실제 문제 해결 → 안전한 실행 → 성공 과정 재현 → 직접 따라하기 훈련**을 하나의 흐름으로 연결하는 실행형 AI Git 코치를 구상했습니다.

# Q3-1. 어떤 문제를 해결하며, 기존 방식 대비 차별성은 무엇인가요?

Git 사용자가 겪는 핵심 문제는 단순히 명령어를 모르는 것이 아닙니다. **현재 저장소 상태에서 어떤 명령을 사용해야 안전한지 판단하기 어렵고, 한 번 해결한 문제도 자신의 기술로 체화하기 어렵다는 점**입니다.

기존 강의·블로그·공식 문서는 개념 학습에는 유용하지만 사용자의 현재 브랜치, 커밋, 원격 저장소 상태를 반영하기 어렵습니다. 게임형 Git 학습 서비스는 반복 실습에 강점이 있지만 실제 작업 중 발생한 오류를 현재 맥락에 맞게 해결하는 것과는 차이가 있습니다. 범용 생성형 AI는 질문에 답할 수 있지만, 사용자의 실제 해결 과정을 다시 재현해 반복 훈련시키는 구조는 별도로 필요합니다.

초기 MVP는 세 가지에 집중합니다.

첫째, 사용자가 자연어나 오류 메시지를 입력하면 `git status`, 현재 브랜치, 원격 저장소 등 필요한 상태부터 확인하도록 안내합니다. 둘째, Git Graph로 브랜치와 커밋 흐름을 보여주고 다음 명령과 실행 이유를 단계별로 설명합니다. `reset --hard`, `clean`, 강제 push처럼 데이터 손실 가능성이 있는 명령은 즉시 실행하도록 하지 않고 경고·백업·복구 경로를 먼저 제시합니다.

셋째, 문제가 해결되면 성공 과정을 명령·상태·결과·설명·Git Graph 변화가 포함된 이벤트로 저장합니다. 사용자는 이를 Replay로 다시 보거나 같은 상황을 직접 해결하는 Guided Practice로 전환할 수 있습니다. 오답 시 바로 정답을 노출하기보다 단계별 힌트를 제공하고, 무힌트 재현 성공 여부를 확인합니다.

즉, 차별점은 **“AI에게 물어보고 끝나는 구조”가 아니라 실제 Git 문제를 안전하게 해결하고, 그 해결 경험을 다시 훈련해 사용자의 역량으로 전환하는 구조**입니다.

GitHub 자격증 준비도, Local/Cloud/Hybrid AI, 교육영상 자동 제작은 이 핵심 사용성이 검증된 후 단계적으로 확장합니다.

# Q3-2. 수익 창출 계획은 어떻게 되나요?

초기에는 개인 사용자의 반복 사용과 지불 의사를 먼저 검증하고, 이후 교육기관·기업으로 확장합니다.

개인 사용자는 기본 문제 진단과 제한된 실습을 무료로 이용하고, Pro 구독에서는 고급 오류 진단, 개인별 해결 이력, Replay 저장, 직접 따라하기 훈련, 반복 취약문제 분석 등을 제공합니다. 초기 가격은 월 9,900원을 가설로 두고 실제 사용자 인터뷰와 결제 전환 결과에 따라 조정합니다.

첫 수익 검증 목표는 대규모 가입자 확보보다 **실제 결제 사용자 10명 이상**을 만드는 것입니다. 무료 사용자 중 반복적으로 Git 문제를 해결하고 Replay 훈련까지 이용한 사용자를 중심으로 Pro 전환 의사를 확인합니다.

교육기관·부트캠프·기업에는 학습자별 실습 진행상황, 퀘스트 배포, 자동채점, 반복 오류 분석을 제공하는 기관용 라이선스를 검증합니다. 초기에는 최소 1개 교육기관 또는 팀에서 PoC(Proof of Concept, 실증)를 수행해 실제 도입 의사와 기관 단가를 확인합니다.

후속 단계에서는 GitHub 자격증 준비도 관리, 기업별 보안정책을 반영한 Local/Cloud AI 선택, 숙련자의 성공 작업을 교육콘텐츠로 전환하는 기능을 유료 확장 기능으로 검증합니다.

핵심 수익 검증 지표는 **첫 문제 해결 완료율, 7일 재사용률, Replay 사용률, 무힌트 재현 성공률, 유료 전환 사용자 수, 기관 PoC 여부**입니다.

> 2차 이후 보완 필요: 경쟁 서비스 가격 비교와 사용자 인터뷰를 바탕으로 월 9,900원 가격 가설의 근거를 추가한다.

# Q4-1. 아이디어를 어떻게 사업화하실 계획인가요?

1년 안에 “사용자가 실제 Git 문제를 해결하기 위해 반복적으로 사용하고, 해결 경험을 다시 훈련하며, 이 기능에 비용을 지불하는가”를 검증하겠습니다.

## 1~3개월 — 핵심 MVP

초기 MVP 범위를 세 가지로 제한합니다.

1. **자연어·오류 메시지 기반 Git 문제 진단**
2. **Git Graph + 안전한 단계별 해결 안내**
3. **성공 작업 Replay + 직접 따라하기 훈련**

사용자가 질문하면 먼저 현재 상태를 확인하고, 단계별 명령과 실행 이유를 제시합니다. 위험 명령은 자동 실행하지 않고 백업과 복구 경로를 우선 안내합니다. 문제 해결 후에는 성공 과정을 이벤트 형태로 저장해 Replay와 직접 훈련으로 재사용합니다.

현재 웹 프로토타입에서는 Git Graph, Guided Terminal, AI Coach 3열 화면과 `/api/coach` 기반 단계별 명령 안내 및 고위험 Git 명령 경고 구조를 구현하고 있습니다. 별도의 자격증 준비도 대시보드 화면도 프로토타입으로 제작해 두었지만, **1~3개월 핵심 MVP의 필수 범위에는 포함하지 않습니다.**

개발 저장소:
- https://github.com/MetaStudy999/github-certification-learning-system-web
- 작업 브랜치: `feature/ai-git-coach-mvp`

## 4~6개월 — 사용자 검증

Git 입문자, GitHub 학습자, 현업 개발자 50~100명을 대상으로 베타 테스트를 진행합니다. 다음 지표를 측정합니다.

- 첫 문제 해결 완료율
- 7일 재사용률
- Replay 실행률
- Replay 후 직접 훈련 전환율
- 무힌트 재현 성공률
- 동일 유형 오류의 반복 질문 감소 여부

이 단계에서 사용자 반응이 확인된 기능만 다음 단계로 확장합니다.

## 7~9개월 — 첫 유료 검증

개인 Pro 구독을 소규모로 운영하여 **실제 결제 사용자 10명 이상**을 우선 목표로 검증합니다. 동시에 대학·부트캠프·기업 개발교육팀 중 최소 1곳에서 PoC를 추진합니다.

## 10~12개월 — 검증된 기능 확장

핵심 사용성이 확인된 후 다음 기능을 순차적으로 확장합니다.

- GitHub 자격증 준비도 관리
- Local / Cloud / Hybrid LLM 선택
- 기업용 AI 사용정책
- AI 교육콘텐츠·영상 생성
- CLI / IDE 연동

핵심은 기능 수가 아니라 **실제 문제 해결 → 재사용 → 직접 재현 성공 → 지불 의사**를 데이터로 증명하는 것입니다.

# Q4-2. 책임멘토를 통해 어떤 도움을 받고 싶으신가요?

책임멘토에게 가장 받고 싶은 도움은 현재 기술 아이디어에서 **가장 먼저 돈을 지불할 고객과 핵심 기능을 좁히는 것**입니다.

첫째, Git 입문자, GitHub 학습자, 현업 개발자, 대학·부트캠프·기업 교육팀 중 어느 고객군에서 문제 강도와 지불 의사가 가장 높은지 검증하고 싶습니다.

둘째, 초기 MVP를 자연어 진단, Git Graph 기반 단계 안내, Replay·직접훈련 세 가지로 축소했는데 이 중 실제 구매와 반복 사용을 만드는 핵심 기능이 무엇인지 멘토의 관점에서 검토받고 싶습니다.

셋째, 월 9,900원 개인 구독 가설과 기관 라이선스 모델을 어떤 인터뷰와 PoC로 검증해야 하는지, 첫 유료 사용자 10명과 첫 기관 실증 1곳을 만들기 위한 현실적인 고객접촉 방법을 자문받고 싶습니다.

넷째, 핵심 사용성이 확인된 이후 Local/Cloud AI, GitHub 자격증 준비도, 교육영상 자동 제작 중 어떤 기능이 개인 시장과 기업 시장에서 각각 가장 높은 확장가치를 갖는지 우선순위를 검토받고 싶습니다.

마지막으로 1인 창업자의 개발·영업 병목을 줄이기 위해 어느 시점에 Git 전문가, 교육 콘텐츠 전문가, B2B 영업 파트너를 외부 협력 형태로 보완하는 것이 적절한지 조언받고 싶습니다.

# Q8. 창업자(대표)의 역량과 경험을 적어주세요

공학과 법학을 전공했고, 출판편집디자인·제안서 작성·웹마스터·서버관리·IDC 운영 등 기술과 콘텐츠, 시스템 운영을 함께 경험했습니다. 현재 AI·보안 융합 분야를 학습·연구하면서 Git/GitHub, Linux, AI 도구를 실제 개발환경에서 사용하고 있습니다.

GitHub 자격증 학습을 위해 콘텐츠 저장소와 웹 기반 학습 시스템을 직접 기획·구축하고 있으며, 입문자가 개발환경 설치, Git 명령 실행, 오류 해결, 공식 문서 확인 과정에서 어디에서 막히는지 따라하기 문서와 실습 구조를 만들면서 확인해 왔습니다.

코디세이 GitHub 팀프로젝트에서는 브랜치 분리, 병합, 충돌, 오류 해결을 직접 경험했고 AI 어시스턴트를 활용해 문제를 해결했습니다. 이 경험에서 실제 Git 문제를 현재 상태에 맞춰 시각적으로 설명하고 단계적으로 코칭한 뒤, 해결 경험을 다시 훈련할 수 있는 제품의 필요성을 확인했습니다.

현재 공개 개발 저장소에서 AI Git Coach 웹 프로토타입을 직접 개발하고 있습니다. 프로토타입에는 Git Graph, 단계별 Guided Terminal, AI Coach 인터페이스가 있으며, `/api/coach`에서는 자연어 질문을 단계별 Git 명령으로 변환하고 `reset --hard`, `clean`, force push 등 고위험 명령을 별도로 감지해 안전 확인을 우선하도록 구현하고 있습니다. GitHub 자격증 준비도 대시보드도 별도 프로토타입 화면으로 구현해 두었습니다.

초기 3개월은 핵심 MVP 개발과 사용자 검증에 집중하고, 콘텐츠 제작과 영업은 템플릿·자동화와 외부 자문을 활용해 병목을 줄이겠습니다. 사용자 검증 후에는 Git 전문가, 교육 콘텐츠 전문가, B2B 영업·사업개발 파트너를 단계적으로 협력 구조에 추가할 계획입니다.

# 제출용 MVP와 실제 개발 범위 분리

```text

   ↓

   ↓
```

```text
Core MVP

   └─ CLI / IDE 연동
```
