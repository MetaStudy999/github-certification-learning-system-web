### 핵심 정의

> Git을 설명하는 AI가 아니라, 사용자의 현재 상황을 확인하고 안전한 실행과 결과 검증·복구까지 돕고, 성공 경험을 다시 재현·훈련·교육콘텐츠로 전환하며, 질문·실습 데이터를 바탕으로 Git/GitHub 지식 수준과 자격증 준비도를 체계적으로 관리하는 AI Git 코치.

핵심 흐름:

`Learn → Practice → Assist → Verify → Recover → Replay → Guided Practice → Measure → Re-Learn`

- Learn: 개념·자격증 학습
- Practice: 실제 명령 실습
- Assist: 자연어·오류 메시지 기반 문제 해결
- Verify: 실행 결과 검증
- Recover: 실패 시 복구 경로 안내
- Replay: 성공한 해결 과정을 속도 조절 가능한 시뮬레이션으로 재현
- Guided Practice: 사용자가 직접 다시 따라 하며 훈련
- Measure: 질문·실습·오답·재현 결과를 자격증 학습영역에 연결해 준비도 측정
- Re-Learn: 부족 영역 맞춤 재학습

AI 모델은 작업 특성과 보안 요구에 따라 **Local LLM(로컬 거대언어모델) / Cloud API(클라우드 API) / Hybrid(하이브리드)** 중 선택할 수 있도록 설계한다. 향후에는 보안·비용·난이도에 따라 모델을 자동 선택하는 Auto Mode로 확장한다.

장기적으로는 성공한 실제 작업 히스토리를 AI가 교육 목표와 사용자 수준에 맞게 장면·말풍선·자막·음성 설명으로 재구성하여 개인 맞춤 교육영상으로 전환한다.

# Q2. 아이디어를 떠올린 배경 이야기

저는 Git을 배우기 위해 온라인 강의를 들어 보았지만, 브랜치·커밋·머지 같은 개념이 실제 작업 화면과 연결되지 않아 쉽게 이해되지 않는 부분이 많았습니다. 명령어를 외우는 것과 실제 프로젝트에서 “지금 무엇을 해야 하는지” 판단하는 것은 전혀 다른 문제라는 것을 느꼈습니다.

이 문제를 가장 크게 체감한 것은 코디세이(Codyssey) GitHub 팀프로젝트였습니다. 팀원들과 브랜치를 나누고, 변경사항을 합치고, 충돌과 오류를 해결하는 과정에서 AI 어시스턴트를 활용했습니다. AI에게 현재 상황과 오류 메시지를 질문하면 원인과 해결 방법을 친절하게 설명해 주어 실제 문제를 하나씩 해결할 수 있었습니다. 특히 글로만 설명하는 것보다 Git Graph처럼 브랜치와 커밋의 흐름을 시각적으로 보여주고, 현재 위치에서 다음에 입력해야 할 명령어를 크게 보여주며 “왜 이 명령을 실행하는지”까지 설명해 준다면 입문자가 훨씬 빠르게 이해할 수 있겠다는 생각이 들었습니다.

팀프로젝트를 진행하며 Git은 한 번 강의를 듣는 것으로 익숙해지는 도구가 아니라는 점도 알게 되었습니다. 입문자는 현재 브랜치와 작업 상태를 이해하기 어렵고, 검색으로 찾은 명령을 자신의 상황에 그대로 적용하기도 어렵습니다. 반대로 개발 경험이 있는 사람도 오랜만에 사용하는 `rebase`, `stash`, `cherry-pick`, `reflog` 같은 기능이나 낯선 오류를 만나면 다시 검색하게 됩니다.

또 하나의 문제는 문제를 한 번 성공적으로 해결해도 시간이 지나면 그 해결 과정을 다시 기억하기 어렵다는 점이었습니다. 실제로 해결했던 작업을 명령 순서, Git Graph 변화, AI 설명과 함께 다시 재생하고, 사용자가 직접 같은 상황을 따라 하며 훈련할 수 있다면 단순히 “AI가 대신 해결해 준 경험”이 아니라 “내가 다시 해낼 수 있는 기술”로 바뀔 수 있다고 생각했습니다.

또한 내가 Git과 GitHub를 어느 정도 알고 있고 무엇이 부족한지 체계적으로 파악하기 어렵다는 점도 문제였습니다. 강의를 몇 개 들었는지보다 실제로 어떤 질문을 했고, 어떤 실습에서 성공·실패했으며, 어떤 오류를 반복하고, 같은 문제를 도움 없이 다시 해결할 수 있는지가 더 중요한 학습 데이터라고 생각했습니다. 이 데이터를 GitHub 자격증의 대분류와 하위 학습 항목에 연결하면 자신의 지식 수준을 수치와 목록으로 확인하고 부족한 부분을 다시 학습할 수 있다고 보았습니다.

그래서 “공부할 때만 쓰는 Git 학습 서비스”가 아니라 Git을 사용하는 순간 곁에서 도와주는 코칭 에이전트, 성공 작업 Replay·따라하기 훈련, GitHub 자격증 준비도 대시보드를 하나로 연결하는 아이디어를 구상했습니다. 장기적으로는 성공 작업 히스토리를 AI가 학습 목표와 수준에 맞는 장면·말풍선·자막·음성 설명으로 재구성하여 개인 또는 조직의 교육영상으로 전환하고자 합니다.

입문자는 Git을 눈으로 이해하며 따라하고, 숙련자는 기억나지 않는 기능이나 오류를 빠르게 해결하며, 누구나 실제 해결 경험을 학습 자산으로 축적할 수 있는 학습·실습·문제해결·재현훈련·역량관리 통합형 AI Git 코치를 개발하고자 이 아이디어를 떠올렸습니다.

# Q3-1. 어떤 문제를 해결하며, 기존 방식 대비 차별성은 무엇인가요?

Git 사용자의 핵심 문제는 단순히 ‘명령어를 모르는 것’이 아니라, 현재 저장소 상태에서 어떤 명령을 안전하게 사용해야 하는지 판단하기 어렵고, 문제를 해결한 뒤에도 그 경험을 반복 훈련하거나 자신의 실제 역량으로 축적하기 어렵다는 점입니다.

기존 강의·블로그·공식 문서는 학습에는 유용하지만 사용자의 실제 브랜치·커밋·원격 저장소 상태를 반영하기 어렵습니다. 게임형 Git 학습 앱은 반복학습에 강점이 있지만 실제 개발 중 발생한 오류를 맥락에 맞게 진단하고 해결하는 용도와는 차이가 있습니다. 범용 생성형 AI도 질문에 답할 수 있지만 실제 상태, 장기간의 질문·실습·오답·재현 데이터를 하나의 학습체계로 연결하려면 별도 구조가 필요합니다.

본 아이디어는 Learn(학습) → Practice(실습) → Assist(문제해결) → Verify(검증) → Recover(복구) → Replay(재현) → Guided Practice(직접훈련) → Measure(역량측정) → Re-Learn(재학습)으로 연결합니다. 사용자가 자연어나 오류 메시지를 입력하면 상태를 먼저 확인하고 원인을 설명한 뒤 단계별 명령을 제시합니다. Git Graph로 브랜치·커밋 흐름을 보여주고, 위험 명령은 즉시 실행시키지 않고 경고·백업·복구 가능 여부를 먼저 안내합니다.

또한 사용자는 프로젝트 보안 수준과 목적에 따라 Local LLM(로컬 거대언어모델), Cloud API(클라우드 API), Hybrid(하이브리드) 모드를 선택할 수 있습니다. 비공개 저장소나 민감한 코드 분석은 로컬에서 우선 처리하고, 복잡한 추론·교육콘텐츠 생성은 필요 시 민감정보를 마스킹한 뒤 클라우드 모델을 사용하도록 설계합니다. 기업은 저장소 유형별 모델 사용정책도 설정할 수 있습니다.

문제가 해결되면 성공 작업을 명령·상태·결과·설명·Git Graph 변화가 포함된 이벤트로 저장합니다. 사용자는 속도를 조절해 Replay하거나 같은 문제를 직접 터미널에서 다시 해결할 수 있으며, 오답에는 단계별 힌트를 제공합니다. 질문·실습·오답·재현 결과는 GitHub 자격증별 대분류와 하위 카테고리에 매핑해 준비도와 부족 영역을 보여줍니다.

장기적으로는 성공 히스토리를 AI가 Scene(장면), 말풍선, 자막, 음성 설명으로 구성해 교육영상으로 전환합니다. 즉, 단순 Git 강의나 AI 챗봇이 아니라 현재 문제 해결 → 안전한 실행 → 재현훈련 → 역량측정 → 교육자산화까지 연결하는 실행형 AI Git 코치입니다.

# Q3-2. 수익 창출 계획은 어떻게 되나요?

초기에는 B2C(Business to Consumer, 개인)와 B2B/B2G(Business to Business/Government, 기업·교육기관·공공교육) 수익모델을 병행 검증하겠습니다.

개인 사용자는 기본 Git 학습과 제한된 AI 도움 기능을 무료로 이용하고, Pro 구독에서는 고급 오류 진단, 개인 맞춤 퀘스트, 복구 안내, GitHub 자격증별 준비도·취약영역 분석, 성공 작업 Replay·직접 따라하기 훈련, Local/Cloud/Hybrid AI 모델 선택 기능을 제공합니다. 초기 가격 가설은 월 9,900원이며 실제 결제 전환율로 조정합니다. GitHub Foundations 등 자격증 과정과 브랜치 협업·충돌 해결·Git 복구 같은 직무별 집중 과정은 1회 구매형 패키지로 검증합니다.

대학·직업훈련기관·부트캠프·기업 개발교육팀에는 관리자 대시보드, 퀘스트 배포, 자동채점, 자격증 준비도, Replay 기반 훈련, 조직용 AI 코치를 제공하고 학습자 수 또는 기관 단위 라이선스로 과금합니다. 기업용에서는 비공개 저장소를 Local LLM으로만 처리하거나 Cloud 사용 여부를 관리자가 정책으로 제한할 수 있는 보안형 기능을 차별화 요소로 검증합니다.

후속 단계에서는 숙련자의 실제 해결 과정을 AI가 교육영상과 실습 퀘스트로 변환하는 지식전수 기능, 기업별 Git 규칙과 개발 가이드를 반영한 Private AI Coach로 확장합니다.

초기 핵심 지표는 첫 문제 해결 완료율, 7일 재사용률, Replay 실행률, 무힌트 재현 성공률, 유료 전환, 자격증 학습 지속률, 교육기관·기업 실증입니다.

# Q4-1. 아이디어를 어떻게 사업화하실 계획인가요?

1년 안에 ‘사람들이 Git을 배우기 위해서뿐 아니라 실제 문제를 해결하고, 성공 경험을 다시 훈련하며, 자신의 역량을 관리하기 위해 반복적으로 사용하는가’를 검증하겠습니다.

1~3개월에는 웹 기반 MVP(Minimum Viable Product, 최소기능제품)를 완성합니다. 핵심 기능은 자연어·오류 메시지 입력, 사용자 수준별 설명, Git 상태 확인, 단계별 명령 제안, 위험 명령 경고, 실행 결과 검증, Git Graph 시각화, 퀘스트·자동채점, Git/GitHub 공식 문서 기반 검색, 자격증 준비도 대시보드입니다. AI는 기존 Provider 구조를 활용해 Local·Cloud·Hybrid 모드를 지원하고, MVP에서는 Ollama 기반 로컬 모델 1개와 클라우드 API 모델 1개를 실제 연결해 선택 가능하게 합니다. 비공개 저장소는 Local 우선, Cloud 사용 시 민감정보 마스킹 원칙을 적용합니다.

성공한 문제 해결 과정은 명령·상태·결과·설명 이벤트로 저장해 Replay Mode와 Guided Practice Mode로 재생합니다. 데모에서는 성공 세션 1개를 기준으로 Play/Pause, 0.5x~2.0x, Step, Git Graph 단계 강조, Terminal 명령 재현, AI 설명 동기화, 직접 명령 입력·정오답·힌트까지 검증합니다.

4~6개월에는 입문자, GitHub 자격증 준비생, 현업 개발자 50~100명을 대상으로 베타 테스트를 진행합니다. 첫 문제 해결 완료율, 7일 재사용률, Replay 실행률, 직접 훈련 전환율, 무힌트 성공률, 반복 오류 감소, 자격증 취약영역 개선 정도를 측정합니다. 동시에 사용자가 교육 목표를 입력하면 AI가 저장된 성공 세션을 기반으로 Scene·말풍선·자막·설명문을 생성하는 교육콘텐츠 기능을 최소 검증합니다.

7~9개월에는 개인 Pro 구독과 자격증·직무별 유료 패키지를 판매해 지불 의사를 확인하고, 대학·부트캠프·기업 최소 1곳에서 PoC(실증)를 추진합니다. 기업에는 Private Repo의 Local LLM 강제, Public Repo의 Hybrid 허용 등 조직별 AI 사용정책을 제공하는 모델도 검증합니다.

10~12개월에는 검증 결과에 따라 로컬 CLI/IDE 연동, Auto Routing(보안·비용·난이도 기반 모델 자동선택), AI 음성 설명과 영상 출력까지 확장합니다. 핵심 목표는 기능 수가 아니라 실제 문제 해결, 반복 사용, 재현 성공, 부족 역량 개선, 보안 신뢰, 비용 지불을 데이터로 증명하는 것입니다.

넷째, Replay와 Guided Practice가 실제 학습효과와 재사용률을 높이는지 어떤 지표로 검증해야 하는지, 질문·실습·재현 데이터를 GitHub 자격증 준비도와 연결하는 내부 지표를 어떻게 설계·보정해야 하는지 도움받고 싶습니다.

마지막으로 AI가 실제 성공 작업을 교육영상·실습으로 전환하는 기능이 개인·교육기관·기업 중 어디서 가장 높은 가치를 만드는지, 그리고 소스코드 보호, 개인정보, 지식재산권, 후속 투자 및 TIPS 연결을 위해 어떤 성과지표를 우선 만들어야 하는지 자문받고 싶습니다.

# Q8. 창업자(대표)의 역량과 경험을 적어주세요

# LLM 선택형 AI Provider 방향

현재 레포의 AI Provider 구조(`mock | local | api | hybrid`)를 활용해 다음 모드를 제공한다.

| 모드 | 목적 | 기본 원칙 |
|---|---|---|
| Local Mode | 비공개 저장소·민감 코드 | 외부 전송 없이 로컬 LLM 우선 |
| Cloud Mode | 복잡한 추론·고품질 콘텐츠 | 서버 측 API로 호출, Secret 비노출 |
| Hybrid Mode | 보안과 성능의 균형 | Local 우선 → 필요 시 마스킹 후 Cloud |
| Auto Mode | 후속 확장 | 보안·비용·난이도 기준 자동 라우팅 |

보안 원칙:

- Private Repo는 Local LLM 우선
- Cloud 전송 전 토큰·이메일·경로·민감 코드 마스킹
- API Key는 서버 환경변수에만 저장
- 모델/Provider 사용 여부를 화면에 명확하게 표시
- 기업 관리자는 저장소 유형별 AI 사용정책 설정

MVP 목표:

- Local Ollama 모델 1개 실제 연결
- Cloud API 모델 1개 실제 연결
- Local / Cloud / Hybrid 선택 UI
- 실제 질문 1개를 각 모드에서 검증

# 성공 경험을 학습 자산으로 전환하는 방향

```text
실전 Git 문제
      ↓
AI와 함께 해결
      ↓
성공 세션 이벤트 저장
      ↓
Replay — 성공 과정 다시 보기
      ↓
Guided Practice — 직접 따라하기
      ↓
무힌트 재현 성공 여부 측정
      ↓
GitHub 자격증 준비도 반영
      ↓
부족 영역 재학습
```

후속 확장:

```text
성공 작업 History
      ↓
AI 교육 목표 설정
      ↓
Scene / 말풍선 / 자막 / 설명 생성
      ↓
Git Graph + Terminal 시뮬레이션
      ↓
AI 음성 설명
      ↓
교육영상 출력
      ↓
영상 시청 후 직접 실습
```

핵심 메시지:

> **AI가 답을 대신 주는 것이 아니라, AI와 함께 해결한 경험을 다시 재현하고 직접 수행하게 하여 사용자의 실제 Git 역량으로 전환한다.**

> **실제 업무에서 만들어진 성공 경험을 개인과 조직의 재사용 가능한 교육자산으로 전환한다.**

# GitHub 자격증 역량관리 방향

사용자의 질문·실습·오답·재현 데이터를 다음과 같이 연결한다.

```text
사용자 질문 / 실제 Git 오류 / 퀘스트 실습 / 재현 훈련
        ↓
주제·하위 주제 자동 분류
        ↓
GitHub 자격증별 학습영역 매핑
        ↓
대분류 / 하위 카테고리 이해도 계산
        ↓
내부 학습 준비도 Dashboard
        ↓
부족 항목 추천 실습·퀘스트
        ↓
재실습 후 준비도 갱신
```

대시보드 예시 항목:

- 자격증별 내부 학습 준비도
- 대분류별 이해도
- 하위 카테고리별 이해도
- 질문 수 / 실습 수 / 오답 수
- Replay 실행 횟수
- 직접 재현 성공률
- 무힌트 해결 비율
- 반복적으로 막힌 영역
- 최근 개선된 영역
- 다음 추천 학습·실습

> **주의:** 준비도 수치는 GitHub 공식 합격 확률이 아니라 질문·실습·모의고사·재현훈련 등의 데이터를 기반으로 계산한 서비스 내부 학습지표로 표시한다.
