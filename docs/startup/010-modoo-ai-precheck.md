> Git을 설명하는 AI가 아니라, 사용자의 현재 상황을 확인하고 안전한 실행과 결과 검증·복구까지 돕는 AI Git 코치.

핵심 흐름:

`Learn → Practice → Assist → Verify → Recover → Re-Learn`

- Learn: 개념·자격증 학습

- Verify: 실행 결과 검증
- Recover: 실패 시 복구 경로 안내
- Re-Learn: 부족 영역 맞춤 재학습

# Q2. 아이디어를 떠올린 배경 이야기

저는 Git을 배우기 위해 온라인 강의를 들어 보았지만, 브랜치·커밋·머지 같은 개념이 실제 작업 화면과 연결되지 않아 쉽게 이해되지 않는 부분이 많았습니다. 명령어를 외우는 것과 실제 프로젝트에서 “지금 무엇을 해야 하는지” 판단하는 것은 전혀 다른 문제라는 것을 느꼈습니다.

이 문제를 가장 크게 체감한 것은 코디세이(Codyssey) GitHub 팀프로젝트였습니다. 팀원들과 브랜치를 나누고, 변경사항을 합치고, 충돌과 오류를 해결하는 과정에서 AI 어시스턴트를 활용했습니다. AI에게 현재 상황과 오류 메시지를 질문하면 원인과 해결 방법을 친절하게 설명해 주어 실제 문제를 하나씩 해결할 수 있었습니다. 특히 글로만 설명하는 것보다 Git Graph처럼 브랜치와 커밋의 흐름을 시각적으로 보여주고, 현재 위치에서 다음에 입력해야 할 명령어를 크게 보여주며 “왜 이 명령을 실행하는지”까지 설명해 준다면 입문자가 훨씬 빠르게 이해할 수 있겠다는 생각이 들었습니다.

팀프로젝트를 진행하며 Git은 한 번 강의를 듣는 것으로 익숙해지는 도구가 아니라는 점도 알게 되었습니다. 입문자는 현재 브랜치와 작업 상태를 이해하기 어렵고, 검색으로 찾은 명령을 자신의 상황에 그대로 적용하기도 어렵습니다. 반대로 개발 경험이 있는 사람도 오랜만에 사용하는 `rebase`, `stash`, `cherry-pick`, `reflog` 같은 기능이나 낯선 오류를 만나면 다시 검색하게 됩니다.

그래서 “공부할 때만 쓰는 Git 학습 서비스”가 아니라, Git을 사용하는 바로 그 순간 곁에서 도와주는 코칭 에이전트가 필요하다고 생각했습니다. 사용자가 자연어나 오류 메시지로 질문하면 AI가 현재 상황을 이해하고, Git Graph로 상태를 직관적으로 보여주며, 수준에 맞는 쉬운 설명과 다음 명령을 단계별로 안내하고, 실행 결과까지 확인하는 방식입니다.

이 경험을 바탕으로 입문자는 Git을 눈으로 이해하며 따라하고, 숙련자는 기억나지 않는 기능이나 실제 오류를 빠르게 해결하며, 실전에서 부족했던 부분은 다시 학습으로 연결되는 **학습·실습·문제해결 통합형 AI Git 코치**를 개발하고자 이 아이디어를 떠올렸습니다.

# Q3-1. 어떤 문제를 해결하며, 기존 방식 대비 차별성은 무엇인가요?

Git 사용자의 핵심 문제는 단순히 ‘명령어를 모르는 것’이 아니라, **현재 자신의 저장소 상태에서 어떤 명령을 안전하게 사용해야 하는지 판단하기 어렵다는 점**입니다.

기존 강의·블로그·공식 문서는 학습에는 유용하지만 사용자의 실제 브랜치, 커밋, 원격 저장소 상태를 반영하지 못합니다. 게임형 Git 학습 앱은 실습과 반복학습에 강점이 있지만, 실제 개발 중 발생한 오류를 맥락에 맞게 진단하고 해결하는 용도와는 차이가 있습니다. 범용 생성형 AI 역시 질문 문장만 보고 답할 경우 `reset --hard`, `clean`, 강제 push처럼 데이터 손실 위험이 있는 명령을 사용자의 실제 상태 확인 없이 제시할 수 있습니다.

본 아이디어는 이를 **Learn(학습) → Practice(실습) → Assist(문제해결) → Verify(검증) → Recover(복구)** 흐름으로 해결합니다.

사용자가 자연어나 Git 오류 메시지를 입력하면 먼저 필요한 상태를 확인하도록 안내하고, 결과에 따라 원인을 설명한 뒤 단계별 명령을 제시합니다. 입문자에게는 ‘한 명령씩 따라하기’와 쉬운 설명을 제공하고, 숙련자에게는 핵심 명령과 선택지를 빠르게 보여줍니다. 위험 명령은 즉시 실행시키지 않고 경고, 백업, 복구 가능 여부를 먼저 안내합니다.

또한 사용 중인 Git 버전과 Git/GitHub 공식 문서를 검색해 최신 기준으로 답하도록 하고, 반복적으로 어려워한 개념은 개인 맞춤 퀘스트로 다시 학습하게 합니다.

초기 MVP에서는 사용자의 저장소를 임의로 변경하지 않고 명령 제안·상태 확인·결과 검증에 집중하며, 이후 로컬 CLI(Command Line Interface, 명령줄 인터페이스) 및 IDE(Integrated Development Environment, 통합개발환경) 연동을 통해 사용자의 승인 아래 안전한 실행을 지원할 계획입니다.

즉, 단순 Git 강의나 단순 AI 챗봇이 아니라 **현재 상황을 확인하고, 안전한 실행과 검증·복구까지 연결하는 AI Git 코치**가 차별점입니다.

# Q3-2. 수익 창출 계획은 어떻게 되나요?

초기에는 B2C(Business to Consumer, 개인)와 B2B/B2G(Business to Business/Government, 기업·교육기관·공공교육) 수익모델을 병행 검증하되, 가장 빠르게 지불 의사를 확인할 수 있는 영역부터 집중하겠습니다.

개인 사용자는 기본 Git 학습과 제한된 AI 도움 기능을 무료로 이용하고, Pro 구독에서는 고급 오류 진단, 개인 맞춤 퀘스트, 저장소 상태 기반 가이드, 복구 안내, 자격증 학습 관리 등을 제공합니다. 초기 가격 가설은 월 9,900원이며 실제 결제 전환율을 통해 조정합니다.

GitHub Foundations 등 자격증 과정과 ‘브랜치 협업’, ‘충돌 해결’, ‘Git 복구’ 같은 직무별 집중 과정은 1회 구매형 패키지로 제공할 수 있습니다.

대학, 직업훈련기관, 부트캠프, 기업 개발교육팀에는 관리자 대시보드, 퀘스트 배포, 실습 자동채점, 학습 진도, 조직용 AI 코치 기능을 제공하고 학습자 수 또는 기관 단위 라이선스로 과금합니다.

향후에는 기업의 사내 Git 규칙, 개발 가이드, 저장소 운영정책을 반영한 프라이빗 AI 코치와 CLI/IDE 연동형 기업용 서비스로 확장할 수 있습니다.

초기 사업 검증에서는 무료 가입자 수보다 **첫 문제 해결 완료율, 7일 재사용률, 유료 전환, 교육기관 실증**에 집중합니다. 개인 사용자가 실제로 반복 사용하고 비용을 지불하는지, 동시에 기관이 교육·온보딩 비용 절감 효과를 느끼는지를 비교해 가장 강한 수익모델을 선택하겠습니다.

# Q4-1. 아이디어를 어떻게 사업화하실 계획인가요?

1년 안에 **‘사람들이 Git을 배우기 위해서뿐 아니라 실제 문제를 해결하기 위해 반복적으로 사용하는가’**를 검증하겠습니다.

1~3개월에는 웹 기반 MVP(Minimum Viable Product, 최소기능제품)를 완성합니다. 핵심 기능은 ① 자연어·오류 메시지 입력, ② 사용자 수준별 설명, ③ `git status`, `branch`, `log`, `remote` 등 상태 확인 가이드, ④ 단계별 명령 제안, ⑤ 위험 명령 경고, ⑥ 실행 결과 재확인, ⑦ 기본 Git 퀘스트·자동채점, ⑧ Git/GitHub 공식 문서 기반 최신 정보 검색입니다. 초기에는 사용자의 실제 저장소를 AI가 임의로 변경하지 않도록 하고, 사용자가 직접 실행하거나 격리된 샌드박스에서 검증하도록 설계합니다.

4~6개월에는 입문자, 자격증 준비생, 현업 개발자 등 50~100명을 대상으로 베타 테스트를 진행합니다. 첫 퀘스트 완료율, 문제 해결 완료율, 7일 재사용률, 위험 명령 사전 차단, 같은 문제의 재검색 감소 여부를 측정합니다. 반복 질문은 새로운 퀘스트와 지식베이스 개선에 반영합니다.

7~9개월에는 개인 Pro 구독과 자격증·직무별 유료 패키지를 소규모 판매해 지불 의사를 검증합니다. 동시에 대학·부트캠프·기업 중 최소 1곳에서 실습 자동채점과 관리자 기능을 활용한 PoC(Proof of Concept, 실증)를 추진합니다.

10~12개월에는 가장 반응이 좋은 고객군과 기능에 집중하고, 검증된 경우 로컬 CLI 또는 IDE 확장으로 연결하여 사용자의 승인 아래 저장소 상태를 읽고 명령 실행 전 위험도를 점검하는 기능을 추가합니다.

핵심 목표는 기능 수가 아니라 **실제 Git 문제를 해결했는가, 다시 사용하는가, 비용을 지불하는가**를 데이터로 증명하는 것입니다.

# Q4-2. 책임멘토를 통해 어떤 도움을 받고 싶으신가요?

책임멘토에게 가장 받고 싶은 도움은 기술 아이디어를 **반복 사용과 매출이 발생하는 사업으로 검증하는 과정**입니다.

첫째, 고객 세분화와 PMF(Product-Market Fit, 제품시장적합성) 검증입니다. 잠재 고객은 Git 입문자, GitHub 자격증 준비생, 현업 개발자, 대학·부트캠프·기업 교육팀까지 넓습니다. 어느 고객의 문제 강도와 지불 의사가 가장 높은지, 어떤 순서로 인터뷰·실증해야 하는지 검토받고 싶습니다.

둘째, MVP 범위와 우선순위입니다. 자연어 진단, 상태 확인, 단계별 실행, 위험 명령 경고, 공식 문서 기반 최신 정보 검색, 샌드박스 자동채점 중 무엇을 먼저 구현해야 차별성을 가장 빠르게 입증할 수 있는지 조언이 필요합니다.

셋째, 기존 게임형 Git 학습 서비스 및 범용 생성형 AI와 명확히 구분되는 시장 포지셔닝과 수익모델을 검증받고 싶습니다. 개인 구독, 자격증·직무 패키지, 교육기관 라이선스 중 어떤 모델부터 유료화할지, 기관 PoC를 어떻게 제안할지도 도움받고 싶습니다.

넷째, 실제 저장소와 AI가 연결되는 과정에서 발생할 수 있는 소스코드 보호, 개인정보, 보안, 지식재산권과 오픈소스 라이선스 문제에 대해 전문가 자문을 받고 싶습니다.

마지막으로 초기 사용자 지표와 매출이 확인된 뒤 후속 투자, 지원사업, TIPS(민간투자주도형 기술창업지원) 등 다음 단계로 연결하기 위해 어떤 성과지표를 우선 만들어야 하는지 배우고 싶습니다.

# Q8. 창업자(대표)의 역량과 경험을 적어주세요

저는 컴퓨터공학과 법학을 공부했고, 출판편집디자인·제안서 작성·웹마스터·서버관리·IDC 운영 등 기술과 콘텐츠, 시스템 운영을 함께 경험했습니다. 현재는 AI·보안 융합 분야를 학습·연구하면서 Git/GitHub, Linux, AI 도구를 실제 개발환경에서 지속적으로 활용하고 있습니다.

특히 GitHub 자격증 학습을 위해 학습 콘텐츠 저장소와 웹 기반 학습 시스템을 직접 기획·구축하고 있습니다. 입문자가 개발환경 설치부터 Git 명령 실행, 오류 해결, 공식 문서 확인까지 어느 지점에서 막히는지를 따라하기 문서와 실습 환경을 만들면서 확인해 왔습니다.

이 과정에서 ‘Git 명령어를 배우는 것’과 ‘실제 프로젝트에서 Git 문제를 스스로 해결하는 것’ 사이에 큰 간극이 있다는 점을 체감했습니다. 이것이 본 아이디어를 구상한 직접적인 배경입니다.

저의 강점은 기능 개발만이 아니라 사용자가 이해하기 쉬운 설명, 실습 절차, 오류 대응, 검증 기준, 학습 문서를 하나의 시스템으로 설계할 수 있다는 점입니다. Windows WSL, Ubuntu, macOS 등 서로 다른 개발환경에서 발생하는 설치·권한·명령 문제도 사용자 관점에서 다뤄 왔습니다.

또한 법학 학습 경험을 바탕으로 서비스 운영 시 개인정보, 소스코드 보호, 약관, 지식재산권 등 비기술 요소도 함께 검토할 수 있습니다.

초기에는 1인 창업자로 MVP 개발, 사용자 인터뷰, 콘텐츠 제작, 실증을 직접 수행하고, 검증 결과에 따라 Git 전문가, AI·보안 전문가, 교육 전문가와 협력해 제품을 확장할 계획입니다.
