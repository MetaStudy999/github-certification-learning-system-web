### 핵심 정의

> Git을 설명하는 AI가 아니라, 사용자의 현재 상황을 확인하고 안전한 실행과 결과 검증·복구까지 돕고, 실제 해결 경험을 다시 재현·훈련·교육콘텐츠로 전환하며, 질문·실습 데이터를 바탕으로 자신의 Git/GitHub 지식 수준과 자격증 준비도를 체계적으로 관리하는 AI Git 코치.

핵심 흐름:

`Learn → Practice → Assist → Verify → Recover → Replay → Guided Practice → Measure → Re-Learn`

- Learn: 개념·자격증 학습
- Practice: 실제 명령 실습
- Assist: 자연어·오류 메시지 기반 문제 해결
- Verify: 실행 결과 검증
- Recover: 실패 시 복구 경로 안내
- Replay: 성공한 해결 과정을 속도 조절 가능한 시뮬레이션으로 재현
- Guided Practice: 성공 과정을 사용자가 직접 다시 따라 하며 훈련
- Measure: 질문·실습·오답·재현 결과를 자격증 학습영역에 연결해 준비도 측정
- Re-Learn: 부족 영역 맞춤 재학습

장기적으로는 성공한 실제 작업 히스토리를 AI가 교육 목표와 사용자 수준에 맞게 장면·말풍선·자막·음성 설명으로 재구성하여 **개인 맞춤 교육영상**으로 전환한다.

# Q2. 아이디어를 떠올린 배경 이야기

저는 Git을 배우기 위해 온라인 강의를 들어 보았지만, 브랜치·커밋·머지 같은 개념이 실제 작업 화면과 연결되지 않아 쉽게 이해되지 않는 부분이 많았습니다. 명령어를 외우는 것과 실제 프로젝트에서 “지금 무엇을 해야 하는지” 판단하는 것은 전혀 다른 문제라는 것을 느꼈습니다.

이 문제를 가장 크게 체감한 것은 코디세이(Codyssey) GitHub 팀프로젝트였습니다. 팀원들과 브랜치를 나누고, 변경사항을 합치고, 충돌과 오류를 해결하는 과정에서 AI 어시스턴트를 활용했습니다. AI에게 현재 상황과 오류 메시지를 질문하면 원인과 해결 방법을 친절하게 설명해 주어 실제 문제를 하나씩 해결할 수 있었습니다. 특히 글로만 설명하는 것보다 Git Graph처럼 브랜치와 커밋의 흐름을 시각적으로 보여주고, 현재 위치에서 다음에 입력해야 할 명령어를 크게 보여주며 “왜 이 명령을 실행하는지”까지 설명해 준다면 입문자가 훨씬 빠르게 이해할 수 있겠다는 생각이 들었습니다.

팀프로젝트를 진행하며 Git은 한 번 강의를 듣는 것으로 익숙해지는 도구가 아니라는 점도 알게 되었습니다. 입문자는 현재 브랜치와 작업 상태를 이해하기 어렵고, 검색으로 찾은 명령을 자신의 상황에 그대로 적용하기도 어렵습니다. 반대로 개발 경험이 있는 사람도 오랜만에 사용하는 `rebase`, `stash`, `cherry-pick`, `reflog` 같은 기능이나 낯선 오류를 만나면 다시 검색하게 됩니다.

또 하나의 문제는 **문제를 한 번 성공적으로 해결해도 시간이 지나면 그 해결 과정을 다시 기억하기 어렵다는 점**이었습니다. 실제로 해결했던 작업을 명령 순서, Git Graph 변화, AI 설명과 함께 다시 재생하고, 사용자가 직접 같은 상황을 따라 하며 훈련할 수 있다면 단순히 “AI가 대신 해결해 준 경험”이 아니라 “내가 다시 해낼 수 있는 기술”로 바뀔 수 있다고 생각했습니다.

또한 **내가 Git과 GitHub를 어느 정도 알고 있고 무엇이 부족한지 체계적으로 파악하기 어렵다는 점**도 문제였습니다. 강의를 몇 개 들었는지보다 실제로 어떤 질문을 했고, 어떤 실습에서 성공·실패했으며, 어떤 오류를 반복하고, 같은 문제를 도움 없이 다시 해결할 수 있는지가 더 중요한 학습 데이터라고 생각했습니다. 이 데이터를 GitHub 자격증의 대분류와 하위 학습 항목에 연결하면 자신의 지식 수준을 수치와 목록으로 확인하고 부족한 부분을 다시 학습할 수 있다고 보았습니다.

그래서 “공부할 때만 쓰는 Git 학습 서비스”가 아니라, Git을 사용하는 바로 그 순간 곁에서 도와주는 코칭 에이전트와 **성공 작업 Replay·따라하기 훈련·GitHub 자격증 준비도 대시보드**를 하나로 연결하는 아이디어를 구상했습니다. 사용자가 자연어나 오류 메시지로 질문하면 AI가 현재 상황을 이해하고 Git Graph로 상태를 직관적으로 보여주며, 수준에 맞는 쉬운 설명과 다음 명령을 단계별로 안내합니다. 성공한 해결 과정은 다시 시뮬레이션으로 재현하고 직접 따라 하게 하며, 질문·실습·오답·재현 결과는 자격증별 준비도와 부족한 학습 항목에 반영합니다.

장기적으로는 사용자의 실제 성공 작업 히스토리를 AI가 학습 목표와 수준에 맞는 장면, 말풍선, 자막, 음성 설명으로 재구성하여 개인 또는 조직의 교육영상으로 자동 제작하는 방향까지 확장하고자 합니다.

이 경험을 바탕으로 입문자는 Git을 눈으로 이해하며 따라하고, 숙련자는 기억나지 않는 기능이나 실제 오류를 빠르게 해결하며, 누구나 자신의 실제 해결 경험을 학습 자산으로 축적할 수 있는 **학습·실습·문제해결·재현훈련·역량관리 통합형 AI Git 코치**를 개발하고자 이 아이디어를 떠올렸습니다.

# Q3-1. 어떤 문제를 해결하며, 기존 방식 대비 차별성은 무엇인가요?

Git 사용자의 핵심 문제는 단순히 ‘명령어를 모르는 것’이 아니라, **현재 자신의 저장소 상태에서 어떤 명령을 안전하게 사용해야 하는지 판단하기 어렵고, 문제를 해결한 뒤에도 그 경험을 반복 훈련하거나 자신의 실제 역량으로 축적하기 어렵다는 점**입니다.

기존 강의·블로그·공식 문서는 학습에는 유용하지만 사용자의 실제 브랜치, 커밋, 원격 저장소 상태를 반영하지 못합니다. 게임형 Git 학습 앱은 실습과 반복학습에 강점이 있지만 실제 개발 중 발생한 오류를 맥락에 맞게 진단하고 해결하는 용도와는 차이가 있습니다. 범용 생성형 AI도 질문에 답할 수 있지만 사용자의 실제 상태와 장기간의 질문·실습·오답·재현훈련 데이터를 하나의 학습체계로 연결하는 데는 별도의 구조가 필요합니다.

본 아이디어는 이를 **Learn(학습) → Practice(실습) → Assist(문제해결) → Verify(검증) → Recover(복구) → Replay(재현) → Guided Practice(직접훈련) → Measure(역량측정) → Re-Learn(재학습)** 흐름으로 해결합니다.

사용자가 자연어나 Git 오류 메시지를 입력하면 먼저 필요한 상태를 확인하고 결과에 따라 원인을 설명한 뒤 단계별 명령을 제시합니다. 입문자에게는 ‘한 명령씩 따라하기’와 쉬운 설명, Git Graph 시각화를 제공하고, 숙련자에게는 핵심 명령과 선택지를 빠르게 보여줍니다. `reset --hard`, `clean`, 강제 push 등 위험 명령은 즉시 실행시키지 않고 경고·백업·복구 가능 여부를 먼저 안내합니다.

문제가 해결되면 성공한 작업을 **명령·상태·결과·설명·Git Graph 변화가 포함된 이벤트 로그**로 저장합니다. 사용자는 이를 `0.5x / 1x / 1.5x / 2x / STEP` 속도로 다시 보거나, 같은 문제를 직접 터미널에 명령을 입력해 해결하는 Guided Practice로 전환할 수 있습니다. 오답인 경우 AI가 정답을 즉시 주지 않고 단계별 힌트를 제공하고, 무힌트 성공률·재현 성공률·해결시간을 기록합니다.

또한 질문·실습 성공/실패·오답·Replay·직접 재현 결과를 GitHub 자격증별 대분류와 하위 카테고리에 매핑합니다. 사용자는 대시보드에서 자격증별 내부 학습 준비도, 부족한 영역, 반복 질문 수, 추천 실습을 확인할 수 있습니다. 이 준비도는 공식 합격 확률이 아니라 서비스 내부 학습 지표로 명확히 표시합니다.

장기적으로는 성공한 작업 히스토리를 AI가 교육 목표와 사용자 수준에 맞는 **Scene(장면), 말풍선, 자막, 음성 설명**으로 구성해 개인 맞춤 교육영상으로 자동 제작하고, 영상 시청 후 바로 동일한 실습을 수행하도록 연결합니다.

즉, 단순 Git 강의나 단순 AI 챗봇이 아니라 **현재 Git 문제를 해결하고, 그 성공 경험을 다시 보고 직접 재현하며, 교육콘텐츠와 자격증 학습 데이터로까지 전환하는 실행형 AI Git 코치**가 차별점입니다.

# Q3-2. 수익 창출 계획은 어떻게 되나요?

초기에는 B2C(Business to Consumer, 개인)와 B2B/B2G(Business to Business/Government, 기업·교육기관·공공교육) 수익모델을 병행 검증하되, 가장 빠르게 지불 의사를 확인할 수 있는 영역부터 집중하겠습니다.

개인 사용자는 기본 Git 학습과 제한된 AI 도움 기능을 무료로 이용하고, Pro 구독에서는 고급 오류 진단, 개인 맞춤 퀘스트, 저장소 상태 기반 가이드, 복구 안내, GitHub 자격증별 준비도·취약영역 분석, 성공 작업 Replay 및 직접 따라하기 훈련 등을 제공합니다. 초기 가격 가설은 월 9,900원이며 실제 결제 전환율을 통해 조정합니다.

GitHub Foundations 등 자격증 과정과 ‘브랜치 협업’, ‘충돌 해결’, ‘Git 복구’ 같은 직무별 집중 과정은 1회 구매형 패키지로 제공할 수 있습니다.

대학, 직업훈련기관, 부트캠프, 기업 개발교육팀에는 관리자 대시보드, 퀘스트 배포, 실습 자동채점, 학습 진도와 자격증 준비도, 성공 세션 기반 Replay 훈련, 조직용 AI 코치 기능을 제공하고 학습자 수 또는 기관 단위 라이선스로 과금합니다.

후속 단계에서는 숙련자의 실제 문제 해결 과정을 AI가 교육영상과 실습 퀘스트로 변환하는 기능을 기업·교육기관용 지식전수 도구로 제공할 수 있습니다. 기업의 사내 Git 규칙, 개발 가이드, 저장소 운영정책을 반영한 프라이빗 AI 코치와 CLI/IDE 연동형 서비스로도 확장할 계획입니다.

초기 사업 검증에서는 무료 가입자 수보다 **첫 문제 해결 완료율, 7일 재사용률, Replay 실행률, 직접 재현 성공률, 유료 전환, 자격증 학습 지속률, 교육기관 실증**에 집중합니다.

# Q4-1. 아이디어를 어떻게 사업화하실 계획인가요?

1년 안에 **‘사람들이 Git을 배우기 위해서뿐 아니라 실제 문제를 해결하고, 성공 경험을 다시 훈련하며, 자신의 역량을 관리하기 위해 반복적으로 사용하는가’**를 검증하겠습니다.

1~3개월에는 웹 기반 MVP(Minimum Viable Product, 최소기능제품)를 완성합니다. 핵심 기능은 ① 자연어·오류 메시지 입력, ② 사용자 수준별 설명, ③ `git status`, `branch`, `log`, `remote` 등 상태 확인 가이드, ④ 단계별 명령 제안, ⑤ 위험 명령 경고, ⑥ 실행 결과 재확인, ⑦ Git Graph 시각화, ⑧ 기본 Git 퀘스트·자동채점, ⑨ Git/GitHub 공식 문서 기반 최신 정보 검색, ⑩ 질문·실습·오답 데이터를 GitHub 자격증 학습영역에 연결하는 준비도 대시보드입니다.

초기 MVP에는 성공한 문제 해결 과정을 명령·상태·결과·설명 이벤트로 저장하고 **Replay Mode와 Guided Practice Mode**로 다시 재생하는 기능도 포함합니다. 데모 단계에서는 성공 세션 1개를 기준으로 Play/Pause, `0.5x~2.0x`, Step Forward, Git Graph 단계 강조, Terminal 명령 재현, AI 설명 동기화와 사용자의 직접 명령 입력·정답/오답 판정·힌트 제공까지 구현해 검증합니다. 실제 화면 전체를 동영상으로 녹화하기보다 이벤트 기반 재현을 우선하여 개인정보와 소스코드 노출 위험을 줄입니다.

대시보드는 자격증별 준비도, 대분류와 하위 카테고리 이해도, 부족 질문 수, Replay·재현훈련 성과, 추천 실습을 보여주며 사용자가 ‘무엇을 공부했는가’보다 ‘무엇을 실제로 해낼 수 있는가’를 확인하도록 설계합니다.

4~6개월에는 입문자, GitHub 자격증 준비생, 현업 개발자 등 50~100명을 대상으로 베타 테스트를 진행합니다. 첫 문제 해결 완료율, 퀘스트 완료율, 7일 재사용률, Replay 실행률, Replay 후 직접 훈련 전환율, 무힌트 재현 성공률, 반복 오류 감소, 자격증별 취약영역 개선 정도를 측정합니다.

이 단계에서 **AI 교육콘텐츠 생성 기능의 최소 검증**도 진행합니다. 사용자가 “입문자에게 push 오류를 설명하는 90초 교육자료”처럼 목표를 지정하면 AI가 저장된 성공 세션을 기반으로 Scene 구성, 말풍선, 자막, 설명문 초안을 생성하도록 합니다. MVP에서는 Scene과 자막·설명 생성까지 우선 검증하고, 실제 TTS(Text-to-Speech, 음성합성)와 MP4/WebM 자동 출력은 후속 단계로 둡니다.

7~9개월에는 개인 Pro 구독과 자격증·직무별 유료 패키지를 소규모 판매해 실제 지불 의사를 검증하고, 대학·부트캠프·기업 중 최소 1곳에서 관리자 대시보드와 실습 자동채점, Replay 기반 훈련을 활용한 PoC(Proof of Concept, 실증)를 추진합니다. 조직에서 숙련자의 성공 작업을 교육자료와 재현 실습으로 전환하는 수요도 함께 확인합니다.

10~12개월에는 반응이 좋은 고객군과 기능에 집중하고, 로컬 CLI 또는 IDE 확장으로 연결해 사용자의 승인 아래 실제 저장소 상태를 읽고 명령 실행 전 위험도를 점검하는 기능을 추가합니다. 검증 결과에 따라 AI 음성 설명, 영상 자동 렌더링, 자동 퀴즈·실습 생성까지 확장합니다.

핵심 목표는 기능 수가 아니라 **실제 Git 문제 해결, 반복 사용, 성공 경험 재현, 무힌트 재실행, 부족 역량 개선, 자격증 학습 지속, 비용 지불**을 데이터로 증명하는 것입니다.

# Q4-2. 책임멘토를 통해 어떤 도움을 받고 싶으신가요?

책임멘토에게 가장 받고 싶은 도움은 기술 아이디어를 **반복 사용과 매출이 발생하는 사업으로 검증하는 과정**입니다.

첫째, 고객 세분화와 PMF(Product-Market Fit, 제품시장적합성) 검증입니다. 잠재 고객은 Git 입문자, GitHub 자격증 준비생, 현업 개발자, 대학·부트캠프·기업 교육팀까지 넓습니다. 어느 고객의 문제 강도와 지불 의사가 가장 높은지, 어떤 순서로 인터뷰·실증해야 하는지 검토받고 싶습니다.

둘째, MVP 범위와 우선순위입니다. 자연어 진단, Git Graph, 단계별 문제 해결, 위험 명령 경고, Replay, 직접 따라하기 훈련, 자격증 준비도 대시보드, AI 교육영상 생성 중 어떤 기능을 먼저 검증해야 차별성을 빠르게 입증할 수 있는지 조언이 필요합니다.

셋째, 성공 작업 Replay와 Guided Practice가 실제 학습효과와 재사용률을 높이는지 어떤 지표로 검증해야 하는지, 질문·실습·재현 데이터를 GitHub 자격증 준비도와 연결하는 내부 지표를 어떤 방식으로 설계해야 사용자가 신뢰할 수 있는지 도움받고 싶습니다.

넷째, AI가 실제 개발자의 성공 작업을 Scene·자막·음성 설명·교육영상으로 전환하는 기능이 개인학습, 대학·부트캠프, 기업 온보딩 중 어느 시장에서 가장 높은 가치를 만드는지 검증하고 싶습니다. 특히 기업 내부 지식전수와 교육콘텐츠 자동화가 B2B 수익모델로 연결될 수 있는지 자문받고 싶습니다.

마지막으로 기존 게임형 Git 학습 서비스 및 범용 생성형 AI와 구분되는 시장 포지셔닝, 소스코드 보호, 개인정보, 보안, 지식재산권·오픈소스 라이선스, 후속 투자 및 TIPS 등 다음 단계로 연결하기 위한 성과지표도 함께 검토받고 싶습니다.

# Q8. 창업자(대표)의 역량과 경험을 적어주세요

저는 컴퓨터공학과 법학을 공부했고, 출판편집디자인·제안서 작성·웹마스터·서버관리·IDC 운영 등 기술과 콘텐츠, 시스템 운영을 함께 경험했습니다. 현재는 AI·보안 융합 분야를 학습·연구하면서 Git/GitHub, Linux, AI 도구를 실제 개발환경에서 지속적으로 활용하고 있습니다.

특히 GitHub 자격증 학습을 위해 학습 콘텐츠 저장소와 웹 기반 학습 시스템을 직접 기획·구축하고 있습니다. 입문자가 개발환경 설치부터 Git 명령 실행, 오류 해결, 공식 문서 확인까지 어느 지점에서 막히는지를 따라하기 문서와 실습 환경을 만들면서 확인해 왔습니다.

코디세이 GitHub 팀프로젝트에서는 실제 협업 과정에서 브랜치, 병합, 충돌, 오류 해결을 경험하고 AI 어시스턴트를 활용해 문제를 해결했습니다. 이 경험은 단순히 Git을 가르치는 콘텐츠보다 **실제 사용 중 발생하는 문제를 시각화하고 단계적으로 코칭하는 도구**가 필요하다는 문제의식으로 이어졌습니다.

또한 한 번 해결한 문제를 다시 재현하고 직접 수행해야 실제 역량으로 남는다는 관점에서, 성공 세션을 이벤트로 저장해 Replay와 Guided Practice로 전환하고, 그 결과를 자격증 학습영역에 연결하는 구조를 설계하고 있습니다. 향후 실제 성공 작업을 AI가 교육 목표에 맞는 Scene·자막·설명으로 변환하는 교육콘텐츠 자동화 구조도 단계적으로 검증할 계획입니다.

저의 강점은 기능 개발만이 아니라 사용자가 이해하기 쉬운 설명, 시각화, 실습 절차, 오류 대응, 검증 기준, 학습 데이터를 하나의 시스템으로 설계할 수 있다는 점입니다. Windows WSL, Ubuntu, macOS 등 서로 다른 개발환경의 문제도 사용자 관점에서 다뤄 왔습니다.

초기에는 1인 창업자로 MVP 개발, 사용자 인터뷰, 콘텐츠 제작, 실증을 직접 수행하고, 검증 결과에 따라 Git 전문가, AI·보안 전문가, 교육 전문가와 협력해 제품을 확장할 계획입니다.

# 성공 경험을 학습 자산으로 전환하는 방향

```text
실전 Git 문제
      ↓
AI와 함께 해결
      ↓
성공 세션 이벤트 저장
      ↓
Replay — 성공 과정 다시 보기
      ↓
Guided Practice — 직접 따라하기
      ↓
무힌트 재현 성공 여부 측정
      ↓
GitHub 자격증 준비도 반영
      ↓
부족 영역 재학습
```

후속 확장:

```text
성공 작업 History
      ↓
AI 교육 목표 설정
      ↓
Scene / 말풍선 / 자막 / 설명 생성
      ↓
Git Graph + Terminal 시뮬레이션
      ↓
AI 음성 설명
      ↓
교육영상 출력
      ↓
영상 시청 후 직접 실습
```

핵심 메시지:

> **AI가 답을 대신 주는 것이 아니라, AI와 함께 해결한 경험을 다시 재현하고 직접 수행하게 하여 사용자의 실제 Git 역량으로 전환한다.**

> **실제 업무에서 만들어진 성공 경험을 개인과 조직의 재사용 가능한 교육자산으로 전환한다.**

# GitHub 자격증 역량관리 방향

사용자의 질문·실습·오답·재현 데이터를 다음과 같이 연결한다.

```text
사용자 질문 / 실제 Git 오류 / 퀘스트 실습 / 재현 훈련

주제·하위 주제 자동 분류
        ↓
GitHub 자격증별 학습영역 매핑
        ↓
대분류 / 하위 카테고리 이해도 계산
        ↓
내부 학습 준비도 Dashboard
        ↓
부족 항목 추천 실습·퀘스트
        ↓
재실습 후 준비도 갱신
```

- Replay 실행 횟수
- 직접 재현 성공률
- 무힌트 해결 비율
- 반복적으로 막힌 영역
- 최근 개선된 영역
- 다음 추천 학습·실습

> **주의:** 준비도 수치는 GitHub 공식 합격 확률이 아니라 질문·실습·모의고사·재현훈련 등의 데이터를 기반으로 계산한 서비스 내부 학습지표로 표시한다.
